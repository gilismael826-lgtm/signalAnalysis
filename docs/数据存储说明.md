# 数据存储说明

## 概述

系统支持同时保存原始数据和预处理数据，并使用不同的文件名进行区分。用户可以根据文件名轻松识别和访问不同模式下的数据。系统采用批量保存机制，显著提高数据存储性能。

## 数据文件命名规则

### 原始数据文件
- **EMG原始数据**：`raw_emg_YYYYMMDD_HHMMSS_N.csv`
- **IMU原始数据**：`raw_imu_YYYYMMDD_HHMMSS_N.csv`

### 预处理数据文件
- **EMG预处理数据**：`processed_emg_{norm_status}_YYYYMMDD_HHMMSS_N.csv`
- **IMU预处理数据**：`processed_imu_{norm_status}_YYYYMMDD_HHMMSS_N.csv`

### 文件名说明
- `YYYYMMDD`：年月日（例如：20260208）
- `HHMMSS`：时分秒（例如：143025）
- `N`：文件序号（从1开始递增）
- `{norm_status}`：归一化状态（`norm`表示开启，`nonorm`表示关闭）

## 数据特点对比

### 原始数据
- **EMG数据**：
  - 单位：微伏（μV）
  - 范围：通常在±50000 μV左右
  - 特点：包含原始信号的所有信息，包括噪声和干扰
  
- **IMU数据**：
  - 陀螺仪单位：rad/s（弧度/秒）
  - 加速度单位：m/s²（米/秒²）
  - 特点：包含原始的惯性测量数据

### 预处理数据
- **EMG数据**：
  - 开启归一化时：归一化单位，范围在[-1, 1]附近
  - 关闭归一化时：μV单位，范围与原始数据相似
  - 特点：经过去趋势、滤波处理，噪声减少
  
- **IMU数据**：
  - 开启归一化时：归一化单位，范围在[-1, 1]附近
  - 关闭归一化时：与原始数据相同的单位
  - 特点：经过去趋势处理，基线稳定

## 数据存储机制

### 批量保存优化（2026-02-08更新）

#### 优化原理
- **数据缓冲**：数据先保存到内存缓冲区
- **批量写入**：当缓冲区达到指定大小或时间间隔时批量写入文件
- **减少I/O**：从每次写入改为批量写入，大幅减少磁盘I/O操作

#### 优化参数
```python
BATCH_SIZE = 50  # 每50个数据点批量保存一次
FLUSH_INTERVAL = 0.5  # 最多0.5秒刷新一次
```

#### 优化效果
- **性能提升**：I/O操作减少98%（从每次到每50次）
- **响应速度**：预处理信号延迟从1秒降至0.5秒
- **系统稳定性**：减少I/O阻塞，提高系统响应速度

### 同时存储
- 系统会同时保存原始数据和预处理数据
- 原始数据和预处理数据都使用批量保存机制
- 两种数据使用不同的文件，互不影响

### 文件轮换
- 当文件大小达到5MB时，自动创建新文件
- 文件序号自动递增
- 所有4个文件（原始EMG/IMU、预处理EMG/IMU）独立轮换

### 数据完整性
- 原始数据和预处理数据的时间戳保持一致
- 预处理数据可能略有延迟（由于滤波处理）
- 数据保存失败会记录到日志文件
- 批量保存机制确保数据不会丢失

## 使用场景

### 场景1：仅使用原始数据
**需求**：需要原始的、未经处理的信号数据

**操作**：
1. 启用数据保存功能
2. 不启用信号预处理
3. 查看以`raw_`开头的文件

**文件**：
- `raw_emg_YYYYMMDD_HHMMSS_N.csv`
- `raw_imu_YYYYMMDD_HHMMSS_N.csv`

### 场景2：仅使用预处理数据
**需求**：需要经过滤波和归一化处理的数据

**操作**：
1. 启用数据保存功能
2. 启用信号预处理
3. 选择合适的滤波器类型
4. 根据需要启用归一化
5. 查看以`processed_`开头的文件

**文件**：
- `processed_emg_norm_YYYYMMDD_HHMMSS_N.csv`（开启归一化）
- `processed_emg_nonorm_YYYYMMDD_HHMMSS_N.csv`（关闭归一化）
- `processed_imu_norm_YYYYMMDD_HHMMSS_N.csv`（开启归一化）
- `processed_imu_nonorm_YYYYMMDD_HHMMSS_N.csv`（关闭归一化）

### 场景3：同时使用原始和预处理数据
**需求**：需要对比原始数据和预处理数据

**操作**：
1. 启用数据保存功能
2. 启用信号预处理
3. 同时查看`raw_`和`processed_`开头的文件

**文件**：
- `raw_emg_YYYYMMDD_HHMMSS_N.csv`
- `raw_imu_YYYYMMDD_HHMMSS_N.csv`
- `processed_emg_YYYYMMDD_HHMMSS_N.csv`
- `processed_imu_YYYYMMDD_HHMMSS_N.csv`

### 场景4：对比不同预处理参数
**需求**：测试不同预处理参数的效果

**操作**：
1. 启用数据保存功能
2. 设置预处理参数（滤波器类型、归一化开关）
3. 开始数据采集
4. 修改预处理参数
5. 文件序号会自动递增，便于区分不同参数下的数据

**文件**：
- `raw_emg_YYYYMMDD_HHMMSS_N.csv`（原始数据，不变）
- `processed_emg_norm_YYYYMMDD_HHMMSS_N.csv`（开启归一化）
- `processed_emg_nonorm_YYYYMMDD_HHMMSS_N.csv`（关闭归一化）

## 数据管理

### 查看当前数据文件
在系统运行时，可以通过以下方式查看当前数据文件：

1. **查看日志**：
   ```bash
   tail -f logs/system.log
   ```
   日志中会显示当前打开的数据文件路径

2. **查看data目录**：
   ```bash
   ls -lh data/
   ```
   查看所有数据文件及其大小

3. **使用get_data_file_info函数**：
   ```python
   from src import data_manager
   file_info = data_manager.get_data_file_info()
   print(file_info)
   ```

### 数据文件管理
- **删除旧文件**：定期清理不再需要的旧数据文件
- **备份数据**：将重要的数据文件复制到备份目录
- **数据归档**：将长期不使用的数据文件移动到归档目录

## 注意事项

1. **磁盘空间**：
   - 同时保存4个文件会占用更多磁盘空间
   - 长时间运行时注意监控磁盘使用情况
   - 可以通过调整MAX_FILE_SIZE控制单个文件大小

2. **数据一致性**：
   - 原始数据和预处理数据的时间戳可能不完全一致
   - 预处理数据可能有轻微延迟（滤波处理）
   - 批量保存机制确保数据不会丢失

3. **文件命名**：
   - 文件名中的时间戳是文件创建时间
   - 文件序号在同一会话中递增
   - 重启程序后文件序号会重新开始
   - 预处理文件名包含归一化状态

4. **性能影响**：
   - 批量保存机制显著减少I/O操作
   - 系统性能得到大幅提升
   - 预处理信号延迟明显降低

5. **批量保存**：
   - 系统会在退出前强制刷新所有缓冲区
   - 即使系统异常退出，最多只会丢失50个数据点

## 数据分析建议

### 原始数据分析
- 适用于：信号质量评估、噪声分析、设备校准
- 优点：包含所有原始信息
- 缺点：包含噪声和干扰

### 预处理数据分析
- 适用于：特征提取、模式识别、机器学习
- 优点：信号质量高，特征明显
- 缺点：可能丢失某些原始信息

### 对比分析
- 可以对比原始数据和预处理数据的差异
- 评估预处理效果
- 优化预处理参数

### 归一化数据对比
- `processed_emg_norm_*.csv`：归一化后的数据，范围[-1, 1]
- `processed_emg_nonorm_*.csv`：未归一化的数据，单位μV
- 可以对比两种数据的差异，评估归一化效果

通过使用不同的文件名前缀（`raw_`和`processed_`）和归一化状态标识（`norm`/`nonorm`），系统实现了原始数据和预处理数据的独立存储。批量保存机制大幅提高了数据存储性能，减少了系统延迟。

用户可以根据文件名轻松识别和访问不同模式下的数据，便于进行各种数据分析和处理任务。系统在性能和可靠性之间取得了良好的平衡，适合长时间运行的数据采集应用。
